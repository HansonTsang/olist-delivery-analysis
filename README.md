# Olist 电商履约体验与用户满意度分析

> SQL + Excel Dashboard 商业分析项目  
> 数据集：Brazilian E-Commerce Public Dataset by Olist

## 1. 项目背景

本项目围绕 Olist 巴西电商订单数据，分析配送履约表现与用户满意度之间的关系，并进一步定位应优先治理的地区与商品品类。

核心业务问题：

**配送履约表现如何影响用户评分？平台应该优先优化哪些地区和品类？**

分析区间为 **2017-01 至 2018-08**。2016 年订单记录较少且不连续，因此不纳入正式月度趋势分析。

## 2. 分析框架

```text
数据检查与清洗
    ↓
经营基本盘：订单量 / GMV / 客单价
    ↓
履约表现：配送时长 / 延迟率 / 延迟严重程度
    ↓
用户体验：延迟等级 × 平均评分 / 1–2星差评率
    ↓
问题定位：州级 / 品类级
    ↓
地区 × 品类交叉定位
    ↓
运营优先级与行动建议
```

## 3. 技术栈

- **MySQL / Navicat**：数据清洗、多表 JOIN、聚合分析
- **Excel**：Dashboard 与风险矩阵可视化
- **GitHub**：项目文档与分析代码管理

考虑到本地 MySQL 版本较旧，SQL 尽量使用子查询和中间表，避免依赖 CTE 与窗口函数。

## 4. 数据处理口径

- **延迟订单**：`DATEDIFF(actual_delivery_date, estimated_delivery_date) > 0`
- **差评订单**：`review_score <= 2`
- **Review 去重**：同一订单存在多条评价时，保留 `review_answer_timestamp` 最新的一条
- **订单-品类粒度**：一行代表一个 `order_id × category`；同一订单购买多个同品类商品只计一次
- 支付表可能一单多条记录，因此计算订单支付金额时先按 `order_id` 聚合，避免 JOIN 后重复统计

## 5. 核心发现

### 5.1 平台增长主要来自订单规模扩张

2017-01 至 2018-08：

- 月订单量由 **750** 增长至 **6,351**
- GMV 由约 **12.75 万**增长至约 **98.54 万**
- 客单价由 **170.06** 降至 **155.16**

因此，业务增长主要由订单规模扩张驱动，而非持续提升客单价。

2017 年 11 月订单量与 GMV 同时出现明显峰值；本项目仅将其描述为潜在季节性/促销效应，不直接推断具体原因。

### 5.2 总体延迟率不高，但存在明显长尾

- 有效已交付订单：**96,203**
- 平均配送时长：**12.48 天**
- 延迟订单：**6,531**
- 延迟率：**6.79%**
- 延迟订单平均晚到：**10.62 天**

在全部延迟订单中，约 **43.8% 晚到至少 8 天**，说明履约问题具有明显长尾特征。

### 5.3 延迟与用户满意度呈明显负向关联

| 履约情况 | 平均评分 | 1–2星差评率 |
|---|---:|---:|
| 准时 | 4.29 | 9.25% |
| 晚1–3天 | 3.29 | 32.14% |
| 晚4–7天 | 2.10 | 67.68% |
| 晚8–14天 | 1.67 | 80.15% |
| 晚15天以上 | 1.72 | 78.32% |

即使仅晚 1–3 天，差评率也已经明显上升；晚 4–7 天后，1–2 星差评率超过三分之二。

> 注：这里展示的是数据中的强关联关系，并不将其表述为严格因果关系。

### 5.4 地区问题呈现两种不同模式

- **RJ（里约热内卢州）**：订单规模较大，同时延迟率和延迟严重程度较高，属于典型的**高风险型问题**
- **SP（圣保罗州）**：延迟率相对较低，但订单量巨大，因此产生大量绝对延迟订单，属于**规模驱动型问题**
- SP + RJ 合计贡献约 **50.7%** 的全部延迟订单

因此，运营资源不应简单按照“延迟率最高”排序，而应同时考虑**问题发生率与绝对影响量**。

### 5.5 高风险地区 × 品类组合

重点组合包括：

- **RJ × bed_bath_table**：143 个“延迟 + 1–2星差评”订单，问题率 **10.70%**
- **RJ × sports_leisure**：88 个问题订单，问题率 **9.90%**
- **RJ × computers_accessories**：77 个问题订单，问题率 **9.34%**
- **RJ × furniture_decor**：74 个问题订单，问题率 **9.08%**
- **SP × bed_bath_table**：99 个问题订单，但问题率仅 **2.30%**

这进一步说明：RJ 更接近“履约质量风险”，而 SP 更多体现为订单基数带来的绝对影响量。

## 6. 运营建议

1. **优先排查 RJ 高销量品类的配送链路**  
   聚焦 bed_bath_table、sports_leisure、computers_accessories、furniture_decor 等品类，进一步分析承运商、配送路线、仓配节点及 SLA。

2. **重点降低严重长尾延迟，而非只追求总体延迟率下降**  
   总体延迟率仅 6.79%，但延迟订单平均晚到 10.62 天，且超过 3 天后差评风险明显恶化。

3. **对 SP 采用规模型监控策略**  
   SP 的问题订单绝对量高，但问题发生率较低，应通过大盘监控和局部流程优化降低绝对问题量，而不是将其视为系统性服务质量失效。
